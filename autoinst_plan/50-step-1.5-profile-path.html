Step 1.5 Design — Profile Path (CobblerProfileCommand#updateCobblerFields)

1. Research findings (verified against the code, 2026-10-08)

  1. Profile-level kernel options have exactly one writer. KickstartDetailsEditAction#processCobblerFormValues (java/core/src/main/java/com/redhat/rhn/frontend/action/kickstart/KickstartDetailsEditAction.java:366) sets both kernelOptions and postKernelOptions from the profile details form onto a CobblerProfileEditCommand and calls store(). No other code path sets kernel options on a CobblerProfileCommand.
  2. The convergence point is CobblerProfileCommand#updateCobblerFields (java/core/src/main/java/com/redhat/rhn/manager/kickstart/cobbler/CobblerProfileCommand.java:77): if (kernelOptions != null) profile.setKernelOptions(Optional.of(kernelOptions)); — the raw string is pushed to the cobbler profile verbatim. Both CobblerProfileEditCommand#store and CobblerProfileCreateCommand#store route through it, so create and edit share one site.
  3. Every other updateCobblerFields caller leaves kernelOptions null and therefore skips the block entirely: taskomatic KickstartFileSyncTask / CobblerSyncTask, CobblerProfileSyncCommand#createProfile, CobblerDistroCreateCommand, KickstartWizardHelper (profile create), BaseKickstartCommand#store, XML-RPC ProfileHandler#setKickstartTree, KickstartSoftwareEditAction. Wiring inside the if block cannot affect them. (The setKernelOptions hits in KickstartScheduleCommand, SSMScheduleCommand, SystemHandler, ScheduleKickstartWizardAction are on the system path — steps 1.3 / 2.6 — not on profile commands.)
  4. Round-trip semantics. Cobbler stores kernel options as a dict; a string setter value is parsed cobbler-side (shlex-like). The UI form round-trip renders the cobbler dict via CobblerObject.convertOptionsMap into the text field, showing CobblerObject.INHERIT_KEY (<<inherit>>) when the profile has no options. KernelOptionsList parsing keeps quote characters inside tokens, so key="a b" survives parse→serialize unchanged; <<inherit>> and the empty string round-trip identically.
  5. Routing key exists: KickstartData#getInstallType() (java/core/src/main/java/com/redhat/rhn/domain/kickstart/KickstartData.java:823) resolves tree → install type, null-safe. CobblerProfileCommand carries an optional user (null for the taskomatic constructor) — matching the §5.5 user-context semantics of the installer-updates lookup.
  6. Test infra: CobblerCommandTestBase defaults to a mocked cobbler connection (the connection class is resolved from config; the test rhn.conf maps it to the mock), so CobblerCommandTest profile tests run DB-backed without a live cobbler — the same way step 1.2’s tree-operation tests ran on the agent VM.
  7. No kickstart-host concept exists on the profile path (no request context, no operation serverName). profileOptions is empty today so the FQDN is unused — but the factory validates it non-empty, and G6 will need a real value.

2. Decisions locked in this round (planning round 4)

  1. postKernelOptions stays untouched. Spec §5.4 only mandates the kernel options field; step-1.2 precedent (kernelOptionsPost untouched). Post options keep flowing as raw strings.
  2. Routing failures propagate. A KernelOptionsBuilderException (blank java.hostname, missing tree/install type, unknown install type) is not caught — consistent with the locked step-1.1/1.2 “unknown install type throws” stance. Unreachable in practice: only the UI details-edit path sets kernelOptions, and that path requires a valid profile with a tree; all automated callers leave it null (finding 3). Accepted new failure mode for degenerate data, mirroring the distro path’s hard hostname dependency.
  3. Shared FQDN helper extracted — no duplicate helpers: the ConfigDefaults-based canonical-hostname resolution moves into a small static helper used by both BaseTreeEditOperation (delegating) and CobblerProfileCommand. No behavior change for the tree path.
  4. Wiring at the convergence point only. KickstartDetailsEditAction needs no change — the roadmap’s KickstartDetailsEditAction → CobblerProfileCommand#updateCobblerFields arrow already exists in code, and the command layer covers create + edit + any future caller.
  5. profileOptions remains empty (step-1.1 decision 4): this step wires the seam so the G6 flip is a one-line builder override, not a call-site sweep. Cobbler’s tftpgen keeps owning the installer-selection option on PXE entries.

3. Code design

All changes under java/core/src/main/java/com/redhat/rhn/.

3.1 KickstartHostHelper (new, com.redhat.rhn.manager.kickstart)

Placed next to KickstartUrlHelper — both consumers live in the manager.kickstart.* namespace. One function (revised after the plan acknowledgment, see §9): a provided server FQDN is canonicalized; null/empty falls back to the configured Java hostname unchanged — canonicalizing it could resolve to a container-internal name instead of the external FQDN that has to be used:

public class KickstartHostHelper {
    private KickstartHostHelper() { }

    public static String getServerFqdn(String serverFqdn) {
        if (serverFqdn == null || serverFqdn.isEmpty()) {
            return ConfigDefaults.get().getJavaHostname();
        }
        try {
            return InetAddress.getByName(serverFqdn).getCanonicalHostName();
        }
        catch (UnknownHostException e) {
            return serverFqdn;
        }
    }
}

3.2 BaseTreeEditOperation (refactor, behavior unchanged)

java/core/src/main/java/com/redhat/rhn/manager/kickstart/tree/BaseTreeEditOperation.java loses its inline FQDN resolution entirely — no wrapper method is kept; applyDistroKernelOptions() calls the helper directly (the InetAddress/ UnknownHostException/ConfigDefaults imports are dropped):

protected void applyDistroKernelOptions() {
    KernelOptionsList options = new KernelOptionsList(this.tree.getKernelOptions());
    options.addMissingOptions(KernelOptionsBuilderFactory
            .getBuilder(this.tree.getInstallType(),
                    KickstartHostHelper.getServerFqdn(this.serverName), this.user)
            .distroOptions(this.tree));
    this.tree.setKernelOptions(options.toString());
}

One documented delta vs. the pre-refactor code: when the operation’s serverName is blank, the configured Java hostname is now used as-is instead of being canonicalized (see §4) — a provided serverName is still canonicalized, so the UI path (request.getLocalName()) is unaffected and the DB-free merge tests (which canonicalize a provided name) pass unchanged.

The step-1.2 tests (TreeCreateOperationTest, the DB-free merge test) keep passing.

3.3 CobblerProfileCommand#updateCobblerFields (the wiring)

Replace the raw push:

if (kernelOptions != null) {
    KernelOptionsList options = new KernelOptionsList(kernelOptions);
    options.addMissingOptions(KernelOptionsBuilderFactory
            .getBuilder(ksData.getInstallType(), KickstartHostHelper.getServerFqdn(null), user)
            .profileOptions(profile));
    profile.setKernelOptions(Optional.of(options.toString()));
}
  • ksData.getInstallType() — routing key (finding 5); the factory throws on null/unknown per decision 2.
  • user passed through — user-scoped installer-updates lookup once profileOptions becomes non-empty; null (taskomatic) → org-global, per 20-kernel-options.md §5.5.
  • profileOptions(profile) receives the cobbler profile being written — empty today (decision 5), so the merge is a no-op and the saved string is the parsed/normalized user input.
  • postKernelOptions block stays byte-identical (decision 1).
  • New imports: KernelOptionsList, KernelOptionsBuilderFactory, KickstartHostHelper.

No schema, UI/JSP, Struts or XML-RPC API changes.

4. Behavior deltas (parity register)

Delta Reason / notes
Whitespace normalization of saved profile kernel options (multiple spaces collapse, leading/trailing trim) KernelOptionsList parse→serialize; same documented normalization class as step 1.2 (spec §5.1.1).
<<inherit>>, empty string, quoted values round-trip unchanged Verified against KernelOptionsList parsing (quotes stay in tokens) and cobbler INHERIT_KEY handling — legacy parity.
profileOptions merge is a no-op today Empty until G6 (decision 5); idempotent under repeated store.
Routing failure → KernelOptionsBuilderException propagates Decision 2. New failure mode, unreachable for existing rhnKSInstallType labels; automated paths never set kernelOptions.
Blank serverName on the tree path → configured Java hostname used as-is (no canonicalization); a provided name is still canonicalized Helper revision (§9): protective against container-internal resolution — the configured hostname is the external FQDN; legacy canonicalized both cases.
postKernelOptions still pushed raw Decision 1.

5. Test plan

5.1 DB-backed (CobblerCommandTest, runs on the agent VM / CI)

Fixture: CobblerCommandTestBase (PostgreSQL + mocked cobbler connection). Assertions read the stored options back via Profile.lookupById(...) + convertOptionsMap(prof.getKernelOptions().get()) — the same rendering the details UI uses (exact mechanics settled while implementing).

  • Normalization — setKernelOptions(" opt1=val1 opt2 ") → store → profile options equal opt1=val1 opt2.
  • Quoting — key="value with spaces" round-trips with quotes preserved.
  • Legacy parity — <<inherit>> → <<inherit>>; "" → "".
  • Idempotency — store twice (create, then edit round-trip) yields an identical options string.
  • Post options untouched — post_kernel_options string stored verbatim (incl. unnormalized spacing).

The fixture’s tree install type does not change the assertions (profileOptions is empty); routing is exercised implicitly — store() must not throw.

5.2 DB-free

None new: KernelOptionsList parse/serialize and factory routing are already covered by the step-1.1 suites. KickstartHostHelper’s UnknownHostException fallback needs rhn.conf/ConfigDefaults on the classpath — covered by the DB-backed suite only (same note as step-1.2 §5.2). A tiny pure test for canonicalize may be added if it stays trivial; otherwise skip (no dead weight).

9. Implementation notes (2026-10-08)

  • Implementation followed §3: KickstartHostHelper added under com.redhat.rhn.manager.kickstart, BaseTreeEditOperation#getServerFqdn delegates to it, CobblerProfileCommand#updateCobblerFields routes the user string through KernelOptionsList + the factory-routed (empty) profileOptions merge.
  • Helper revision after the plan acknowledgment: the initial two-function design (canonicalize + localServerFqdn) was replaced by a single getServerFqdn(String serverFqdn) — a provided FQDN is canonicalized, null/empty falls back to the configured Java hostname unchanged. Rationale: “local” naming and canonicalizing the configured value could resolve to a container-internal name instead of the external FQDN that has to be used. Parity delta registered in §4. On review, the temporary BaseTreeEditOperation#getServerFqdn() wrapper was dropped — applyDistroKernelOptions() calls the helper directly.
  • Test mechanics: the cobbler mock (MockConnection) stores string setter values raw and interprets the literal <<inherit>> as inherit on read-back and "" as an empty dict — mirroring cobbler itself, so the parity assertions of §5.1 are meaningful. String round-trips are asserted via assertEquals(expected, prof.getKernelOptions().get()) (the established pattern, cf. SystemHandlerProvisioningTest). A dedicated null-options test (testProfileEditWithoutKernelOptions) guards the if (kernelOptions != null) skip used by all automated callers.
  • The fixture tree (CobblerCommandTestBase → KickstartableTreeTest) carries a real rhnKSInstallType row, so the factory routing in updateCobblerFields never sees an unknown type — ksData.getInstallType() is always non-null on the paths that set kernel options.
  • Checkstyle: mvn -f java compile checkstyle:checkstyle clean (ant toolchain dropped per user decision).
  • Verification: local — 44 DB-free tests green (builder/factory/list + step-1.2 merge) after the helper revision, checkstyle clean. Agent VM (two windows: initial implementation ~20:30–20:40 CEST, helper revision ~22:55–23:05 CEST): mgradm stop → dedicated uyuni-test-pgsql container (worktree mounted at /manager, branch schema with opensuse16.1 loaded) → 67 tests green each time (CobblerCommandTest 16 incl. the 7 new profile-options cases, 41 builder/factory/list, 10 tree-op) → container removed, mgradm start, deployed stack healthy (spacewalk-java-5.3.1-260400.1.2.uyuni6.noarch, unchanged).
