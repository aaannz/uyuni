Step 1.1 — Port builder hierarchy (status: DONE 2026-10-08)

  • Implemented per 20-kernel-options.md §2–§4 and the step design in 30-step-1.1-builders.md: interface, abstract base (configurable serverFqdn, optional User context), factory, builders Rhel / AutoYast / Agama under com.suse.manager.autoinstallation.{builder,installer}; no Debian builder (no debian/ubuntu install type exists — unroutable dead code, decision recorded in the step design §1.3).

Phase 3 — Saltboot integration (G3)

Step 3.1 — Saltboot deployment model design (status: DONE 2026-10-19)

  • Design in 90-step-3.1-saltboot-model.md; decisions promoted to 00-goals.md §5.9.
  • Two entity families: suseSaltbootBranch (branch settings per branch group, proxy FK resolved to the primary FQDN, naming, default boot image/kernel parameters; replaces saltboot-group) and hierarchical suseSaltbootConfig (JSONB partitioning with parent chain, assigned to groups/systems; replaces saltboot), plus suseSaltbootTerminal (per-terminal state + force flags).
  • Effective config = deep merge by disk/partition IDs along the chain (JSON null tombstones); resolution system > most-derived > priority > notification (A/B rollouts that only switch the image).
  • Transition: idempotent upgrade-time migration (UpgradeCommand) + dual-write from the formula-save hooks; users unassign formulas when ready. Containerized proxies only; boot image refs are lax strings.
  • Verification correction: today’s formula merge replaces edit-group values and keeps only one group’s data per formula (step doc §1.2) — migration maps per-system partitioning to root configs.
