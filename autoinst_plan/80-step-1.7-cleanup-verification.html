4.2 Agent-VM session (window ~09:40–11:05 CEST 2026-10-12)

Deployment learnings (recorded in AGENTS_CUSTOM.md §3):

  • uyuni-server.service runs podman run --rm with Restart=on-success, ExecStartPre=podman rm --force and --health-on-failure=stop: any clean PID1 exit recreates the container and discards the writable layer. The login-page healthcheck (30 s interval, 3 retries) fails during every tomcat restart, so the deploy script’s -r path (rctomcat/rctaskomatic) always cycles the container and wipes the freshly deployed webapp. A temporary unit drop-in redefining ExecStart with --health-on-failure=none made deploys + direct podman exec uyuni-server systemctl restart tomcat|taskomatic safe (verified: container survives, canary persists). Drop-in removed after the session.
  • First backend deploy of the branch (deploy.sh backend) also required the branch’s unapplied DB deltas: the deployed 2026.08 stack reports the same schema package version as the branch, so 91-schema-update.sh skips them. Applied manually: schema/spacewalk/upgrade/next/ (001, 100, 101, 500, 520, 540, 550) and, after the RBAC boot validator demanded them, the fresh-install access data (namespace.sql, accessGroup.sql, endpoint.sql, endpointNamespace.sql, accessGroupNamespace.sql — all idempotent ON CONFLICT DO NOTHING; re-run duplicate-key errors are benign). Without this, SparkFilter fails at boot (transactional_mode does not exist, then RbacRouteValidationException for 5 branch endpoints).
  • opensuse16.1 seeded into rhnKsInstallType (id 13) from the branch upgrade SQL; visible via kickstart.tree.listInstallTypes.
