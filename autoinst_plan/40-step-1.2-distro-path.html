Step 1.2 Design — Distro Path (TreeCreateOperation / BaseTreeEditOperation)

1. Research findings (corrections to round-1 spec wording)

Verified against the code on 2026-10-08; the round-1 spec (§5.1 of 20-kernel-options.md) is inaccurate on two points.

  1. The edit path never recomputes options today. TreeEditOperation only overrides getCobblerCommand(); BaseTreeEditOperation#store persists whatever tree.kernelOptions holds. The spec’s “effectively re-runs on edit” is only true indirectly: the computed options were persisted at create time and the Struts edit form round-trips them.
  2. XML-RPC kickstart.tree.update wipes computed options. The handler (java/core/src/main/java/com/redhat/rhn/frontend/xmlrpc/kickstart/tree/KickstartTreeHandler.java:294) replaces kernelOptions with the caller’s string; install=/self_update=/ root=live: disappear from the DB and get pushed to the Cobbler distro like that (PXE breakage). rename (line 328) does not touch options.
  3. Install type is editable on edit (BaseTreeAction#processCommandSetters sets it from the form on create and edit; the XML-RPC update likewise). Changing it today never adds the new install type’s options (SLES15 → SLE16 switch leaves the tree without root=live:).
  4. serverName is null on the XML-RPC update/rename paths. Only create sets it (ConfigDefaults.getJavaHostname(), KickstartTreeHandler.java:164); the Struts form sets request.getLocalName() (BaseTreeAction.java:111). The factory throws KernelOptionsBuilderException on a null/empty FQDN, so naive edit-path wiring would break the update API.
  5. Legacy substring guards cross-match. contains("self_update=") also matches inst.self_update=; contains("root=") matches any *root= (e.g. nfsroot=) — user options can spuriously suppress computed ones.
  6. Legacy StringJoiner leaves a leading space when the user-typed options are empty (" install=http://...").
  7. TreeCreateOperationTest#testCreateRhelistro uses rhel_7 and expects empty options — it will fail after migration because of the locked step-1.1 deviation (inst.repo= unconditional for rhel/fedora/generic) and must be updated.

2. Decisions locked in this round (planning round 3)

  1. The builder merge runs on create AND edit. It is wired into BaseTreeEditOperation#store, so TreeCreateOperation (via super.store()), the Struts edit path and the XML-RPC update/rename paths all share one call site. This fixes findings 2 and 3. Accepted behavior change: options the user deliberately deletes re-appear on the next edit/store (protective; these are computed “make it work” options). TreeDeleteOperation overrides store() entirely and is unaffected.
  2. FQDN fallback for a blank serverName: resolve ConfigDefaults.getJavaHostname() through the same InetAddress.getByName(...).getCanonicalHostName() chain as before (mirrors what XML-RPC create passes). This also repairs the empty-string edge case, where legacy code produced a broken install=http:///... URL.
  3. kernelOptionsPost is untouched — the legacy distro path never writes it, and the builder has no post-options concept in Phase 1.
  4. DB-backed tests run on the agent VM (single shared VM, coordinate via agents-workbench/autoinstallation/session-log.md). The deployed uyuni-db lacks opensuse16.1 in rhnKsInstallType (verified live 2026-10-08) and must not be used for branch tests. When the running Uyuni is not needed, shut it down with mgradm stop — that frees port 5432 so the standard java/Makefile.docker test-container flow works without port remapping.
  5. Normalizations accepted (§4) — parsed-key checks replace substring checks, leading space removed; the parity tests compare modulo these.

3. Code design

All changes under java/core/src/main/java/com/redhat/rhn/manager/kickstart/tree/.

3.1 BaseTreeEditOperation

  • getServerFqdn() moves here from TreeCreateOperation, extended with the fallback (decision 2):
protected String getServerFqdn() {
    String host = this.serverName;
    if (host == null || host.isEmpty()) {
        host = ConfigDefaults.get().getJavaHostname();
    }
    try {
        return InetAddress.getByName(host).getCanonicalHostName();
    }
    catch (UnknownHostException e) {
        return host;
    }
}
  • New merge helper — the single home of the distro-path merge pattern (20-kernel-options.md §5.1: user-typed options win):
protected void applyDistroKernelOptions() {
    KernelOptionsList options = new KernelOptionsList(this.tree.getKernelOptions());
    options.addMissingOptions(KernelOptionsBuilderFactory
            .getBuilder(this.tree.getInstallType(), getServerFqdn(), this.user)
            .distroOptions(this.tree));
    this.tree.setKernelOptions(options.toString());
}
  • store(): call applyDistroKernelOptions() immediately before KickstartFactory.saveKickstartableTree(this.tree) — after label/basePath validation, before the tree is saved and before the Cobbler command store + distro.setKernelOptions(...) push, so every consumer sees the merged result. Coverage:
  • create: TreeCreateOperation#store → super.store()
  • edit (UI and XML-RPC update): TreeEditOperation via base store()
  • rename: base store() (no-op while the options are complete)
  • delete: TreeDeleteOperation overrides store() — unaffected

3.2 TreeCreateOperation

  • store() keeps only the duplicate-label check and super.store(); the inline kernel-options block, getSelfUpdateOption() and getServerFqdn() are deleted (the merge happens in the base).
  • Unused imports removed (Channel, Optional, StringJoiner, InetAddress, UnknownHostException).

No schema, API or UI changes; the XML-RPC kickstart.tree.update contract is unchanged (its effect on kernel options improves, see §4).

4. Behavior deltas (parity register)

Delta Reason / notes
Edit/update re-adds missing computed options; install-type change on edit adds the new type’s options Decision 1; fixes the XML-RPC update wipe (finding 2) and the install-type-change gap (finding 3). Stale old-type options are not removed — add-missing only.
Parsed-key checks replace substring contains() nfsroot= no longer suppresses root=live:; inst.self_update= no longer suppresses a self_update= add on the SLES15 path (finding 5). Bug fixes, documented.
No leading space when user-typed options are empty StringJoiner artifact removal (finding 6).
inst.repo= for all rhel/fedora/generic types (incl. rhel_6/7, fedora18, generic_rpm) Locked step-1.1 deviation (RHEL gate dropped).
Blank serverName → ConfigDefaults.getJavaHostname() instead of blank-host URL Decision 2; legacy produced install=http:///... in that edge.
Distro options are merged only after base-path validation succeeds The legacy create path set the options string before validateBasePath() ran, so a tree with an invalid initrd kept mutated options while store() returned an error. The merge now lives after validation; the pre-existing SUSE-type tests only passed because they ignored store()’s result (see §9).
Unknown install type → KernelOptionsBuilderException Locked step-1.1 decision; unreachable for existing rhnKSInstallType labels (all route).

9. Implementation notes (2026-10-08)

Deviations and discoveries recorded while implementing:

  • Step-1.1 defect repaired: RhelKernelOptionsBuilder#systemOptions emitted inst.ks=<url>; the committed step-1.1 test and the behavioural spec (20-kernel-options.md §5.3) require ks=<url> (matching the legacy initiate path, KickstartInitiateAction). Fixed to ks=; the red testSystemOptions is green again.
  • Test fixture gap: TreeOperationTestBase (via KickstartTestUtils.setupTestConfiguration) only ever created RHEL-style kernel/initrd files under /tmp/kickstart/images; SUSE install types resolve /boot/x86_64/loader/*, so every SUSE-type store() failed with kickstart.tree.invalidinitrd. The pre-existing SUSE tests masked this by ignoring store()’s return value and asserting the prematurely set option string (see the validation-order delta in §4). The test base now also creates the SUSE loader layout (with the org set so isRhnTree() is false and no mount-point prefix is applied).
  • Checkstyle without ant: the sandbox and the VM lack a working ant checkstyle chain (no ant/ivy on the sandbox; Tumbleweed repos on the VM lack ivy, obs-to-maven and the toolchain). Checkstyle 10.12.7 (the exact version pinned by manager-build.xml) was run over all of java/core/src via the CLI with the same config/properties — audit clean.
